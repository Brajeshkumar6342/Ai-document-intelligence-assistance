# AI Document Intelligence Assistant (Local, Free RAG Pipeline)

A RAG (Retrieval-Augmented Generation) system that answers questions about
your documents — running entirely on your machine, no API keys or cost.

## Stack
- **Embeddings**: `sentence-transformers` (`all-MiniLM-L6-v2`) via HuggingFace
- **Vector store**: Chroma (local, persisted to disk)
- **LLM**: Ollama (`llama3` or `phi3`, running locally)
- **Orchestration**: LangChain

## 1. Install Ollama (the local LLM runner)

Download and install from https://ollama.com (Windows/Mac/Linux all supported).

Then pull a model:

```bash
ollama pull llama3
```

If your laptop is low on RAM (under 16GB), use the smaller, faster model instead:

```bash
ollama pull phi3
```

...and change `LLM_MODEL = "llama3"` to `LLM_MODEL = "phi3"` in `rag_assistant.py`.

Ollama runs a background server automatically after install — verify with:

```bash
ollama list
```

## 2. Install Python dependencies

```bash
cd rag_assistant
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## 3. Add documents to index

Drop a few `.pdf` or `.txt` files into `sample_docs/`. (A couple of PDFs — your
own notes, a company handbook, whatever — work well for a demo.)

## 4. Build the index (run once per document set)

```bash
python rag_assistant.py ingest
```

This will:
1. Load every PDF/TXT in `sample_docs/`
2. Split them into ~500-character overlapping chunks
3. Generate embeddings for each chunk
4. Store them in a local Chroma vector database (`chroma_db/`)

## 5. Ask questions

```bash
python rag_assistant.py ask "What is the main topic of this document?"
```

You'll get an answer generated by the local LLM, grounded in the retrieved
chunks, plus the source chunks it used (for citation/traceability).

## What to say in your interview about this project

- **Why RAG instead of fine-tuning?** RAG lets you update the knowledge base
  instantly (just re-ingest) without retraining a model, and it grounds
  answers in real source documents — reducing hallucination and enabling
  citations.
- **Why chunking with overlap?** Overlap (50 chars here) prevents a fact from
  being split awkwardly across two chunks and losing meaning at the boundary.
- **Why a local/free stack?** Cost control and data privacy — nothing leaves
  your machine, useful for sensitive documents.
- **Known limitation to mention:** naive fixed-size chunking can split
  mid-sentence; a production version would use semantic or
  recursive-by-structure chunking, and add re-ranking after retrieval.
- **How you'd scale it:** swap Chroma for a managed vector DB (Pinecone,
  Weaviate, pgvector), add caching, and move the LLM to a hosted endpoint
  for concurrent users.
